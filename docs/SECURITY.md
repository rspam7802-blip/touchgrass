# Security

How TouchGrass addresses the OWASP API Security Top 10 (2023) and the OWASP Mobile Top 10 (2024), what the Phase 12 review changed, and what remains a deliberate, recorded risk. The build spec's privacy requirements (DPDP Act 2023) are covered under API3 and M6.

## Phase 12 review: findings and fixes

| Finding                                                                                                                                                          | Severity | Fix                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web pages had no Content-Security-Policy                                                                                                                         | Medium   | `apps/web/next.config.ts` sends a CSP: same-origin scripts/styles/requests, images from HTTPS + the media origin, only the OpenStreetMap frame (live viewer), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri`/`form-action 'self'` |
| `glob` 9–14.0.1 (GHSA-3g3m-2fjr-6pw4) and `minimatch` < 11.0.1 (GHSA-g3hv-75wg-m249) reachable through OpenTelemetry's GCP detector and Sentry's bundler plugins | Moderate | `pnpm` override to `glob` 14.0.2 (same API, brings `minimatch` 11) in `pnpm-workspace.yaml`                                                                                                                                                  |
| Form-field borders below 3:1 contrast (not security, found in the same pass)                                                                                     | —        | See A11Y.md                                                                                                                                                                                                                                  |
| Featured plans stayed pinned after a cancellation (integrity)                                                                                                    | Low      | Cancelling clears the pin (D-122)                                                                                                                                                                                                            |
| Android app allowed OS backups of app data                                                                                                                       | Low      | `android.allowBackup: false` in `app.config.ts` (cached screens and preferences stay on the device)                                                                                                                                          |

Store review sign-in (D-142): one configured number gets one configured 6-digit code instead of an SMS, so store reviewers can sign in. It's an authentication exception, so it is limited: it's off unless both values are set, the development code is refused, wrong guesses burn the same 5 attempts per code and hit the same per-number and per-IP limits, and the account is an ordinary member. Rotate the code after each review and clear both values when no review is pending (`auth.int` "store review sign-in", `env.test`).

Accepted, recorded risks (dev/build tooling only, never run on user input):

- `minimatch` < 11.0.1 in ESLint and Expo's fingerprint tool: v11 changes the API those tools call. CI's audit gate fails on **high**, so this is reported, not suppressed.
- `deepmerge` prototype poisoning (GHSA-gcqx-w48m-w2h4, low) in `@expo/config`, which runs at build time on our own app config; no patched version exists. Ignored in `pnpm-workspace.yaml` with this rationale.
- `zod` 3.x inside `@expo/cli` (GHSA-mrhx-c7xc-m3w5): developer CLI only (D-010).

Re-evaluate all three on every Expo SDK upgrade.

## OWASP API Security Top 10 (2023)

| Risk                                                     | How it's handled                                                                                                                                                                                                                                                                                                                                                                                               | Where / tests                                                                                                                                          |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **API1 Broken object-level authorisation**               | Every object read goes through a pure policy function: `canViewEvent`, `profileAccess`, chat gates per conversation kind, crew visibility, Lore visibility, staff city scope (`cityScopeFor`). Non-visible objects answer 404, not 403, so existence doesn't leak.                                                                                                                                             | `event.policy`, `profile.policy`, `admin-scope` unit tests; privacy suites in `events.int`, `chat.int`, `after.int`, `safety.int`, `admin-console.int` |
| **API2 Broken authentication**                           | Phone OTP (6 digits, 5-minute TTL, 30 s resend, 10 attempts per phone / 30 per IP per 15 min), HS256 access tokens of 15 minutes, rotating refresh tokens (60 days) with reuse detection that revokes the session, server-side session revocation checked on every request; dev OTP bypass refused in production by config                                                                                     | `auth.int`, `auth.units`, `jwt.test`                                                                                                                   |
| **API3 Broken object property-level authorisation**      | Responses are built from shared Zod schemas (no entity passthrough); `EventViewService` is the only serializer for plans (exact location only after reveal, never to non-attendees); public projections for share pages, profiles and crews carry only listed fields. Requests are parsed with Zod, so unknown properties are dropped (no mass assignment)                                                     | mystery-leak tests in `events.int`; `notifications.int` public views                                                                                   |
| **API4 Unrestricted resource consumption**               | Global per-user (300/min) and anonymous per-IP (600/min) limits, stricter per-route limits (OTP, invites, reports, messages, RSVPs, plotting, verification, live points, city waitlist); JSON bodies capped at 256 KB; uploads go straight to S3 by presigned POST with a size cap (10 MB images) and content-type policy; cursor pagination with capped `limit` everywhere; feed candidate pool capped at 400 | `rate-limit.guard.test`, media upload tests in `profile.int`                                                                                           |
| **API5 Broken function-level authorisation**             | `@Roles` guard on every admin route from one shared section matrix (`ADMIN_SECTIONS`); staff city scope for curators; super-admin-only flags and team; last super admin can't be removed                                                                                                                                                                                                                       | `admin.int`, `admin-console.int` (members, support and curators refused per section)                                                                   |
| **API6 Unrestricted access to sensitive business flows** | Idempotency keys on retryable writes (RSVP, payments, invites, checkout, admin creates); seat changes under a Redis lock + row lock (no overbooking under 50 concurrent RSVPs); waitlist offers single-claim; referral and pass abuse checks; money only confirmed by signed webhooks                                                                                                                          | concurrency tests in `events.int`, `payments.int`, `engagement.int`; k6 `rsvp.js` overbooking counter                                                  |
| **API7 Server-side request forgery**                     | The API never fetches user-supplied URLs. Outbound calls go only to fixed adapter endpoints (SMS, push, payments, weather, storage, analytics) configured by environment                                                                                                                                                                                                                                       | adapters in `src/adapters`                                                                                                                             |
| **API8 Security misconfiguration**                       | Helmet on the API, CORS limited to configured origins without credentials, secrets validated at boot (≥ 32 chars), production refuses fake adapters (`env.ts`) and the dev OTP code (`otp.service.ts`); web sends CSP, HSTS, `X-Frame-Options: DENY`, `nosniff`, a strict referrer policy and `Permissions-Policy`; admin cookies are `httpOnly`, `secure` in production, `SameSite=Strict`, path `/admin`     | `env.test`, Playwright `landing.spec` (security headers)                                                                                               |
| **API9 Improper inventory management**                   | One versioned API (`/v1`), OpenAPI generated from the Zod schemas, no undocumented routes; realtime serves no feature HTTP routes; the boot test pins every module, provider and scheduled job                                                                                                                                                                                                                 | `boot.int`                                                                                                                                             |
| **API10 Unsafe consumption of APIs**                     | Razorpay webhooks are verified by HMAC signature before any state change and applied idempotently by the worker; adapter responses parsed with schemas; failures don't leak upstream detail                                                                                                                                                                                                                    | `payments.int` (forged signatures rejected, duplicate deliveries applied once)                                                                         |

## OWASP Mobile Top 10 (2024)

| Risk                                           | How it's handled                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **M1 Improper credential usage**               | No secrets in the app bundle: the app only knows public URLs (`app.config.ts` extras). Tokens are per device and per session.                                                                                                                                                                                                                                                                                                                                                                                                    |
| **M2 Inadequate supply chain security**        | Exact pinned dependencies (Expo modules on Expo's `~` ranges), lockfile committed, CI runs `pnpm audit --prod --audit-level high`, dependency review on pull requests, gitleaks secret scanning. EAS builds from the repository only.                                                                                                                                                                                                                                                                                            |
| **M3 Insecure authentication / authorisation** | Server-side authorisation only (the app never decides access). Access tokens are short-lived; refresh rotation with reuse detection; "sign out everywhere" and the sessions list revoke server-side.                                                                                                                                                                                                                                                                                                                             |
| **M4 Insufficient input/output validation**    | Every request and response is parsed with the shared Zod schemas on both sides; deep links are matched against the known routes before navigating; push payload URLs are checked against the app scheme.                                                                                                                                                                                                                                                                                                                         |
| **M5 Insecure communication**                  | HTTPS only in production (HSTS on web, App Transport Security on iOS, Android 9+'s default block on cleartext); WebSockets over TLS. No certificate pinning (see risks below).                                                                                                                                                                                                                                                                                                                                                   |
| **M6 Inadequate privacy controls**             | Contacts are matched by SHA-256 hashes of E.164 numbers (raw numbers never leave the phone; phone numbers are low-entropy, so the server treats these hashes as personal data, keeps them only for matching and erases them with the account), location is approximate unless a plan is revealed, live-location points expire (24 h purge), EXIF/GPS is stripped from every upload, analytics carry no personal data (guarded), and data export plus account deletion cover every module (`AccountDataRegistry`, DPDP Act 2023). |
| **M7 Insufficient binary protections**         | Hermes bytecode in release builds; no secrets to extract. Code obfuscation beyond Hermes isn't used (no secrets or proprietary logic on device).                                                                                                                                                                                                                                                                                                                                                                                 |
| **M8 Security misconfiguration**               | Android `allowBackup` off, no debuggable release builds, verified app links / universal links (`assetlinks.json`, AASA) for `/e`, `/u`, `/c`, `/claim`, `/invite`; push links only open our own scheme (`push-links.tsx`); permissions asked for in context.                                                                                                                                                                                                                                                                     |
| **M9 Insecure data storage**                   | Access and refresh tokens in `expo-secure-store` (Keychain / Keystore, `src/lib/secure-storage.ts`). The offline query cache in AsyncStorage holds only allow-listed, non-secret screens and is wiped on sign-out (D-115).                                                                                                                                                                                                                                                                                                       |
| **M10 Insufficient cryptography**              | No custom crypto: HMAC-SHA256 for signed links and calendar feeds; SHA-256 with a server-side pepper for OTP codes, invite/claim/checkout tokens and venue staff PINs (PIN attempts are rate-limited with a lockout across IPs); TLS for transport; KMS-encrypted RDS, S3 and Secrets Manager in production.                                                                                                                                                                                                                     |

## Remaining risks and follow-ups (tracked in LAUNCH_CHECKLIST.md)

- **No certificate pinning** in the app: rotating pins with CloudFront/ACM is operationally risky for a small team; HSTS + ATS + platform trust stores are relied on. Revisit if threat model changes.
- **Admin sign-in is phone OTP only.** Before launch, restrict `/admin` to the office VPN or an IP allow-list at the WAF, and keep the team small (team page, D-127).
- **CSP allows `'unsafe-inline'` scripts** (Next.js inline bootstrap). Moving to per-request nonces is a hardening follow-up.
- A third-party penetration test before public launch.
