## Phase 12 accessibility pass

What changed, and what checks it from now on:

- **Static audit of every mobile screen** (`apps/mobile/__tests__/a11y-audit.test.ts`, D-137): every pressable has a role and label, every input and switch a label, every image a label or is marked decorative, and all text goes through the kit's `Text` (font scaling capped at 200%). Fixed by it: plan covers and Lore grid images marked decorative (the card's label already says what they show); chat photos labelled "Photo from {name}".
- **Contrast:** form-field borders were below 3:1 (WCAG 1.4.11). They now use the `inputBorder` token in both themes on mobile and web (D-135). `tokens.test.ts` pins text, muted text, primary, danger, focus ring and input border pairs.
- **Reflow (WCAG 1.4.10, 1.4.4):** the landing, plan share and not-found pages were checked at 320 px wide and at 200% text size (`e2e/reflow.spec.ts`): no horizontal scrolling. Fixed: wrapping header and navigation, description lists that shrink, long words breaking.
- **Admin sweep:** axe (WCAG 2.1 AA) runs on all 23 admin pages (`e2e/sweep-admin.spec.ts`).
- **Languages:** every Telugu and Hindi string is checked for its own script (D-136).
- **Permission prompts:** every system permission prompt explains the use in plain words (D-141).

Still to do by a person (in `LAUNCH_CHECKLIST.md`): a VoiceOver (iOS) and TalkBack (Android) pass on physical devices of the main flows (sign-up, discover, plan detail, pull up, chat, check-in, safety), with system font at the largest size, and a native-speaker read of Telugu and Hindi. These can't run in CI. The automated checks above and Maestro flows on the CI emulator cover regressions.

## Launch audit (D-163)

- **Legal pages** (`/privacy`, `/terms`, `/refunds`, `/contact`): one `h1`, labelled sections, a labelled "Legal" footer navigation; axe (WCAG 2.1 AA) clean in `e2e/legal.spec.ts`.
- **App:** the new Back button (Settings, Profile), SOS button (busy and failure states announced as text with a retry), venue save toggle, onboarding "Open settings" and "Sign out", and the Legal rows in Settings all have roles and labels; confirmations (sign out, remove from squad, leave crew) use the system alert, which screen readers announce. The static audit (`__tests__/a11y-audit.test.ts`) passes on every screen.
- **Video stories (D-164):** a video story is announced as "Video story from <name>"; the composer preview as "Your video, N seconds". With a screen reader on, stories don't move on by themselves, but a video still plays, and Pause stops it.
